- Create: `tests/scenarios/display_demo.toml` — scenario TOML
- Modify: `crates/sim-runner/src/cli.rs` — add `SimMode::Display` variant

- Modify: `tests/golden_trace_test.sh` — add `display` test case
- Modify: `crates/sim-runner/build.rs` — compile `main_display.c` for display mode

**Implementation steps:**
1. Create `c_firmware/app/main_display.c` — firmware that:
   - Initializes a 320x240 RGB565 display via `sim_display_init(0, 320, 240, 0)` 
   - Initializes a touch screen via `sim_touch_init(0, 0)`
   - Enables display and sets backlight
   - Draws shapes (rectangles, patterned pixels) using `sim_display_fill_rect` and `sim_display_set_pixel`
   - Polls touch events with `sim_touch_get_event` (reads queued events injected by scenario)
   - Uses sim_trace_u32 to emit trace events for verification
   - Follows existing firmware pattern: includes `FreeRTOS.h`, `task.h`, `sim_abi.h`, defines idle/timer task memory, has `c_sim_display_main()` entry
2. Build `main_display.c` in `crates/sim-runner/build.rs` — conditionally compile for display mode
3. Add `SimMode::Display` to `crates/sim-runner/src/cli.rs`
4. Add `--mode display` parsing and `c_sim_display_main()` call in `crates/sim-runner/src/run.rs`
5. Create `tests/scenarios/display_demo.toml` — minimal scenario with one machine
6. Build and run: `cargo run -- --golden --mode display 2>/dev/null > tests/traces/expected_display.trace`
7. Verify golden trace is non-empty and deterministic
8. Add `display` case to `tests/golden_trace_test.sh`

**Verification:**

### Task H4: Return World to Session after Run Stream Exits

**Files to modify:**
- Modify: `crates/sim-grpc/src/server.rs` — call `self.sessions.return_world()` in all sim thread exit paths
- Modify: `crates/sim-grpc/src/session.rs` — ensure `return_world` is called (already defined)

**Current state:** The `return_world` method exists on `SessionMap` but is `#[allow(dead_code)]`. The sim thread in `server.rs` takes World from the session via `take_world()` and then drops it when done. The World is never returned, so post-run operations like `InspectDevices` fail.

**Implementation:**
1. Remove `#[allow(dead_code)]` from `return_world` in session.rs
2. In server.rs `run()` method, the sim thread currently has 3 exit paths where World is dropped:
   - Stop command (line 442-453): World is dropped silently
   - all_idle / no events (line 468-477): World is dropped silently
   - Run error (line 480-489): World is dropped silently
3. Each exit path needs to call `self.sessions.return_world(session_id, world, state, n_events, error)`
4. Since `self` (SimulatorServiceImpl) is used inside the `std::thread::spawn` closure, we need Arc<SessionMap>. Currently `self.sessions` is `SessionMap` owned by the struct. Change to `Arc<SessionMap>`. Actually, SessionMap is already built around `Mutex<HashMap>`, so wrapping in Arc is straightforward.
5. Update `SimulatorServiceImpl` to use `Arc<SessionMap>` internally.

**Actually, let me re-read the code more carefully.** The current code in server.rs does:
```rust
let mut world = self.sessions.take_world(session_id).map_err(Status::not_found)?;
```
Then spawns a thread that moves `world` and `cmd_rx`, `event_tx`. At the end of the thread, the World is just dropped.

The fix:
- In `SimulatorServiceImpl`, store `sessions: Arc<SessionMap>` instead of `sessions: SessionMap`
- Clone `sessions` into the thread closure
- In each exit path, call `sessions.return_world(session_id, world, ...)` before return

**Verification:**
```bash

cargo test -p sim-world  # existing tests still pass
```

### Task H3: Proper Keyframe Serialization

**Files to modify:**
- Modify: `crates/sim-world/src/world.rs` — expand `WorldKeyframe` with machine state
- Modify: `crates/sim-grpc/src/session.rs` — serialize/deserialize keyframe properly
- Possibly: `crates/sim-world/src/machine.rs` — add serializable snapshot of Machine state

**Current state:** `WorldKeyframe` has `now`, `scenario_toml` (empty placeholder), `trace_offsets`. The session `save_keyframe` creates empty `Vec<u8>` data. `load_keyframe` doesn't actually restore World state — it just reads keyframe data but doesn't apply it.

**Design:**
1. Add to `WorldKeyframe`:
   - `machine_snapshots: BTreeMap<u64, MachineSnapshot>` — per-machine event queue state, TCB/fiber state
   - `link_snapshots: Vec<LinkSnapshot>` — pending packets in FIFO channels
   - `bus_snapshots: Vec<CanBusSnapshot>` — pending frames on CAN buses
2. Add `MachineSnapshot` struct with:
   - Event queue state (remaining events with their scheduled times)
   - Virtual time offset
   - Trace event count
3. Serialize `WorldKeyframe` to/from `Vec<u8>` using serde (requires `Serialize`/`Deserialize` derives)
4. Update `save_keyframe()` to serialize to `Vec<u8>`
5. Update `load_keyframe()` to rebuild World from keyframe by:
   - Rebuilding from stored scenario_toml
   - Fast-forwarding to keyframe time
   - Restoring event queue state

**Verification:**
